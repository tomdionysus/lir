# Lir - The Conformance Gate

What "supports MQTT" means for Lir: every normative statement of MQTT 5.0
and 3.1.1, by its identifier, against the test that proves it. Written on
2026-11-20 (step 2 of `TODO/2026-11-19-premise-and-audit.md`).

How it was made:
- The statements are taken whole from the OASIS Standards as published
  (`mqtt-v5.0-os.html`, 252 statements; `mqtt-v3.1.1-os.html`, 139),
  each with the text before its identifier. 3.1.1's conformance appendix
  numbers some statements differently from its body (a known erratum);
  the body is used. Two 5.0 statements carry their identifier only in the
  appendix (`MQTT-3.2.2-8`, `MQTT-4.2.0-1`).
- Each statement was read against `lir/test/*.cpp` at `8965693` by
  reading the tests, not by running them. No build or run was made.
- **tested**: a test asserts what the statement requires. **partial**: a
  test runs the path but does not assert the statement, or asserts part
  of it, or (for 3.1.1) runs only at 5.0 where 3.1.1 differs. **none**: no
  test proves it, whatever the code does. **n/a**: cannot bind Lir.
- **Binds**: whom the statement binds. Lir is a Server and ships a client
  library (`lir/client`); a Client statement is judged against that.
- **Nodes**: "many" where, in a cluster in which any node accepts any
  client, the behaviour depends on state or delivery across nodes. Every
  test named here runs on one node unless it is in `cluster_test.cpp`, so
  a "tested" statement marked "many" is proven on one node only.

A verdict of "tested" says a test exists and asserts the statement. It
does not say the code is right across nodes, which is the audit's other
half (step 3).

## What the gate shows

Where Lir stands on 2026-11-20, from the tables below.

1. **Most of MQTT is not proven.** Of 252 statements in 5.0, 84 are
   tested, the rest partial or untested; of 139 in 3.1.1, 51. "All of
   MQTT", as the README and the record had it, was felt. By the notes
   against them, the code for most statements marked "none" exists: they
   are untested, not absent.
2. **Nothing that bears on more than one node is proven across nodes,
   bar a handful.** The cross-node tests (`cluster_test.cpp`) cover plain
   delivery, retained replace and clear, an immediate will, the SUBACK
   hold, take-over and session resumption on another node. Every other
   statement marked "many" is tested, if at all, on one node.
3. **3.1.1 barely runs at protocol level 4.** Nearly every broker test
   runs at 5.0. Wills, take-over, keep-alive, a second CONNECT,
   UNSUBSCRIBE and QoS 2 at 3.1.1, and the closes 3.1.1 makes where 5.0
   sends a reason code, are never run.
4. **The client library's own duties are unproven.** `client_test.cpp`
   checks outcomes end to end, not the wire: packet ids, DUP, PINGREQ,
   Receive Maximum, the server's limits. It has no QoS 2, no AUTH and no
   WebSocket, so those Client statements are "none".
5. **Whole areas untested:** the CONNACK capability settings
   (`maximum_qos`, `retain_available`), the "MUST NOT send if it would
   exceed the Maximum Packet Size" rules (21 statements; they hold today
   because Lir never sends those properties), most reason-code tables,
   QoS 2's packet-id echoes and PUBREL resend, ordering (4.6), and the four
   behavioural rules of shared subscriptions (4.8.2-3 to 6).

Defects found on the way, each read in the code and confirmed (none is
fixed; findings go to Tom first):

- **Resend order** (`[MQTT-4.6.0-1]`): the broker resends in-flight
  deliveries by walking a map keyed by packet id
  (`lir/broker/broker.cpp:919`, `broker.h:439`), and so does the client
  library (`lir/client/client.cpp:237`). Once ids wrap past 65535 a resend
  goes out in id order, not the order first sent.
- **A Subscription Identifier on a client's PUBLISH is accepted**
  (`[MQTT-3.3.4-6]` makes it a Protocol Error): the decoder allows it in a
  PUBLISH because a server sends one, and nothing refuses it inbound.
- **MQTT 3.1**: three deviations, in its section below.
- **Possibly** (the mapper's reading, not yet confirmed): the client
  library does not close on Session Present 1 when it holds no session
  (`[MQTT-3.2.2-4]`, `lir/client/client.cpp:207`).

Noted, not a defect: a 3.1.1 session with CleanSession 0 ends after
`maximum_session_expiry` (7 days by default, `broker.cpp:307`); 3.1.1 has
no expiry of its own, so this is the operator's policy.

## MQTT 3.1

MQTT 3.1 (IBM and Eurotech, 2010) numbers no statements. What follows is
where it differs from 3.1.1 in what a Server must do, each against Lir as
read on 2026-11-20. Elsewhere 3.1 is taken to be as 3.1.1.

| Where 3.1 differs | Lir | Test |
|---|---|---|
| Protocol name `MQIsdp`, level 3 | Decoded and encoded | `mqtt_packet_test.cpp:MqttPacket.V31SpeaksMQIsdp`; `broker_test.cpp:BrokerTest.ConnectsEveryVersion` |
| WebSocket subprotocol `mqttv3.1` | Chosen | `websocket_test.cpp` (the `mqttv3.1` case) |
| A client identifier of 1 to 23 characters; outside that, CONNACK return code 2 | An empty identifier is refused (`broker/broker.cpp:215`). One longer than 23 is accepted: a deviation, if a lenient one | none |
| CONNACK's first byte is reserved: there is no session present flag | Lir sets bit 0 when a 3.1 client resumes a session (`broker/broker.cpp:316`, `mqtt/packet.cpp:292`): a deviation | none |
| SUBACK carries a granted QoS per filter and has no failure code | Lir's 3.x SUBACK allows `0x80` (`mqtt/packet.cpp:36`, `:350`), which a 3.1 client cannot read: a deviation | none |

So 3.1 is reached, and three of its differences are not honoured. None is
tested at protocol level 3 beyond the CONNECT itself.
